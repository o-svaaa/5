🔐 Как работают сессии на этом сайте

Что такое сессия?

Сессия — это механизм сохранения состояния между HTTP-запросами. В отличие от cookies, данные сессии хранятся на сервере, а клиенту передаётся только идентификатор (Session ID).

Где и как используются сессии?

// В каждом файле, где нужна сессия:
session_start();  // Обязательно в начале файла!

// Сохранение данных в сессию:
$_SESSION['user_id'] = $userId;
$_SESSION['application_id'] = $applicationId;
$_SESSION['user_login'] = $generatedLogin;

// Проверка авторизации:
if (isset($_SESSION['user_id'])) {
    // Пользователь авторизован
}

// Удаление сессии (выход):
session_destroy();

✅ Преимущества сессий перед cookies:
  • Данные хранятся на сервере — безопаснее
  • Нет ограничения на объём данных (4KB, как у cookies)
  • Пользователь не может подменить данные сессии
  • Автоматическое удаление при закрытии браузера (или через session_destroy)

🍪 Как работают Cookies на этом сайте

Что такое Cookies?

Cookies — это небольшие фрагменты данных (до 4KB), которые сервер отправляет браузеру, а браузер хранит их на компьютере пользователя и отправляет обратно при каждом запросе.

Какие cookies использует сайт?

// Установка cookie (в process_form.php):
setcookie('form_data', $cookie_value, time() + 365*24*60*60, '/');
setcookie('form_errors', $cookie_value, 0, '/');

// Чтение cookie (в index.php и form.php):
$saved_data = isset($_COOKIE['form_data']) ? json_decode($_COOKIE['form_data'], true) : null;

// Удаление cookie (после прочтения ошибок):
setcookie('form_errors', '', time() - 3600, '/');
CookieСодержимоеВремя жизниГде используется
form_data JSON с данными формы (ФИО, email, телефон, языки и т.д.) 365 дней index.php — автоматическое заполнение формы при повторном визите
form_errors JSON с ошибками валидации (поле → сообщение об ошибке) До конца сессии браузера index.php — отображение ошибок после редиректа

Схема работы с cookies при отправке формы:

1. Пользователь заполняет форму → POST → process_form.php
                                                    ↓
                                        ❌ Есть ошибки валидации?
                                                    ↓
                                    ДА → сохраняем ошибки в COOKIE
                                    ↓
                                    Редирект на index.php
                                    ↓
                                    Читаем cookie с ошибками
                                    ↓
                                    Отображаем ошибки рядом с полями
                                    ↓
                                    Удаляем cookie с ошибками (показали один раз)
⚠️ Важно: Cookies для form_data сохраняются только для неавторизованных пользователей. При авторизации данные берутся из базы данных, а не из cookies.

🔑 Два типа авторизации

1. Пользовательская авторизация (сессии)

Используется для обычных пользователей, которые хотят редактировать свою анкету. 

// process_form.php — генерация логина и пароля при первой отправке
$generatedLogin = generateLogin($formData['fullname']);  // например: ivanov123
$generatedPassword = generatePassword();                // например: aB4#kL9@mN
$passwordHash = password_hash($generatedPassword, PASSWORD_DEFAULT);

// Сохранение в БД
INSERT INTO users (login, password_hash, application_id) VALUES (..., ..., ...);

// Автоматическая авторизация
$_SESSION['user_id'] = $userId;
$_SESSION['application_id'] = $applicationId;

2. Административная авторизация (HTTP Basic Auth)

Используется для доступа к админ-панели (/admin/). Это встроенный в веб-сервер механизм аутентификации. 

# .htaccess — настройка HTTP Basic Auth
AuthType Basic
AuthName "Admin Panel - Authorization Required"
AuthUserFile /home/u82814/www/5/admin/.htpasswd
Require valid-user

# .htpasswd — хранилище логинов и хешей паролей
# Создаётся командой: htpasswd -c .htpasswd admin
admin:$2y$10$YourHashedPasswordHere

МеханизмСессии PHPВстроенный в Apache/Nginx
Хранение данныхMySQL (таблица users).htpasswd файл
Интерфейс входаHTML-форма (login.php)Всплывающее окно браузера
Возможность выходаЕсть (logout.php)Сложно (требует закрытия браузера)

💡 Технические детали

Безопасность

  • Хеширование паролей: используется password_hash() с алгоритмом BCRYPT
  • Защита от SQL-инъекций: все запросы через PDO с подготовленными выражениями
  • Защита от XSS: htmlspecialchars() при выводе данных
  • HTTP Basic Auth: рекомендуется использовать HTTPS, так как пароль передаётся в base64

Валидация полей

  • ФИО: только буквы (русские/английские), пробелы, дефисы. Длина ≤ 150 символов
  • Email: стандартный формат email, длина ≤ 100 символов
  • Телефон: цифры, +, пробелы, скобки, дефисы. Хотя бы одна цифра
  • Языки программирования: проверка существования в таблице programming_languages
  • Биография: допустимы буквы, цифры, знаки препинания, спецсимволы. Длина ≤ 10000 символов

Генерация логина

// process_form.php
function generateLogin($fullname) {
    // Оставляем только буквы
    $cleanName = preg_replace('/[^a-zA-Zа-яА-ЯёЁ]/u', '', $fullname);
    // Берём первые 15 символов
    $cleanName = substr($cleanName, 0, 15);
    // Добавляем случайное число от 100 до 999
    return strtolower($cleanName) . rand(100, 999);
}

Структура базы данных

applications — основная таблица с анкетами
├── id (INT UNSIGNED, PRIMARY KEY)
├── fullname (VARCHAR 150)
├── email (VARCHAR 100)
├── phone (VARCHAR 50, NULL)
├── birthdate (DATE, NULL)
├── gender (ENUM: male/female/other/unspecified)
├── biography (TEXT, NULL)
├── contract_agreed (TINYINT 1)
└── created_at (TIMESTAMP)

programming_languages — справочник языков
├── id (INT UNSIGNED, PRIMARY KEY)
└── name (VARCHAR 50, UNIQUE)

application_languages — связь many-to-many
├── application_id (INT UNSIGNED, FK → applications.id)
└── language_id (INT UNSIGNED, FK → programming_languages.id)

users — учётные данные пользователей
├── id (INT UNSIGNED, PRIMARY KEY)
├── login (VARCHAR 50, UNIQUE)
├── password_hash (VARCHAR 255)
├── application_id (INT UNSIGNED, FK → applications.id)
└── created_at (TIMESTAMP)
